## 1. 系統簡介

這套系統讓起約方在線上建立合約，邀請兩方或三方簽署。每位簽署人會收到**自己專屬、只能用一次**的簽署連結，用手機或電腦就能完成手寫簽名。全部簽署完成後，系統會產生一份含簽名和稽核紀錄的 PDF，並自動寄給各方。

| 角色 | 做什麼 | 需要帳號嗎 |
|---|---|---|
| 起約方（合約管理者） | 建立合約、上傳文件、選封面、填簽署方資料、發出邀請、追蹤進度、下載 PDF | 不用註冊，打開網站就自動以匿名身分登入 |
| 簽署人（甲方、乙方、丙方） | 打開專屬連結，閱讀合約後簽署、退回修改或拒絕 | 不用，有連結就能簽 |
| 系統維護者 | 部署網站、設定寄信、維護安全規則 | 需要 Firebase 專案權限 |

**主要頁面**

| 網址 | 用途 |
|---|---|
| `/` | 管理台：建立合約、預覽、發出邀請、追蹤進度 |
| `/contracts` | 瀏覽和查詢所有合約 |
| `/contracts/<合約編號>` | 單一合約的內容頁，例如 `/contracts/C-2610001` |
| `/sign/<專屬代碼>` | 簽署人的簽署頁，由系統產生，不需要手動輸入 |

## 2. 開始之前

**瀏覽器**：建議使用最新版 Chrome、Edge、Safari 或 Firefox。手機也能使用，手寫簽名可以直接用手指畫。

**重要：合約綁在「建立它的那個瀏覽器」**。系統用匿名登入辨識起約方，所以「所有合約」只會列出**這個瀏覽器**建立的合約。請留意以下三點：

- 請固定用同一台電腦、同一個瀏覽器管理合約。
- 不要在無痕模式建立正式合約，關閉視窗後就找不回來了。
- 清除瀏覽器的網站資料（Cookie），也會失去這些合約的管理權限。

**寄信設定**：系統會不會自動寄 Email，取決於維護者是否完成 SMTP 設定，詳見[第 8 章](#8-系統維護者部署與設定)。沒有設定時，系統照常運作，但你需要自己把簽署連結轉給對方。

## 3. 起約方：建立並發出合約

打開 <https://mycontractapp-911.web.app>，管理台分成 5 個步驟，從上往下操作即可。

### STEP 1　合約內容

| 欄位 | 說明 |
|---|---|
| 合約編號 | 系統預設自動帶入，例如 `C-2610001`。可以改成你自己的編號，規則見[附錄](#11-附錄編號與統編規則) |
| 合約名稱 | 必填，最多 120 字 |
| 原文語言 | 你填寫內容時使用的語言：繁體中文、簡體中文或 English，翻譯會以它為原文 |
| 摘要 | 一兩句話說明合約重點，會顯示在封面上 |
| 合約條款 | 直接貼上條款文字。如果合約以附件為準，這裡可以留白 |
| 上傳合約文件 | 可上傳 PDF、Word（.docx）、TXT、PNG、JPG，**10 MB 以內** |

上傳文件後，系統會做三件事：

- 從 PDF、Word、TXT 擷取文字，讓簽署人在簽署頁直接閱讀。
- 計算文件的 SHA-256 雜湊值，可以證明文件之後沒有被竄改。
- 如果上傳的是 PDF，最後產生的已簽署 PDF 會把原始 PDF 完整附在後面。

### STEP 2　選擇合約封面

起約方從 6 款封面中選一款，簽署頁和已簽署 PDF 都會使用這款封面。

| 封面 | 風格 |
|---|---|
| 經典藏青 | 深藍底，正式穩重 |
| 商務黑金 | 黑底金色，高級商務 |
| 極簡白 | 白底，簡潔 |
| 科技藍 | 亮藍色系，科技感 |
| 典雅玉綠 | 淺綠底，柔和典雅 |
| 朱印契約 | 米白底加紅色印章邊條，傳統契約風 |

### STEP 3　簽署方

1. 選擇 **兩方** 或 **三方**。
2. 每一方填寫以下欄位：

| 欄位 | 必填 | 說明 |
|---|---|---|
| 角色 | 是 | 預設為甲方、乙方、丙方，可以修改，例如「委託方」 |
| Email | 是 | 簽署邀請和完成通知會寄到這裡，各方不能重複 |
| 公司名稱 | 否 | 個人簽約可以留白 |
| 統一編號 | 否 | 台灣公司填 8 位數字，系統會驗證檢查碼；外國公司可填 1–20 碼英數字 |
| 公司地址 | 否 | 最多 200 字 |
| 代表人 | 否 | 例如公司負責人 |

3. 設定 **簽署期限（天）**：1–90 天，預設 7 天。超過期限，連結就會失效。
4. 按 **建立合約並預覽**。

> 統一編號填錯時，送出前就會提示「統一編號不正確」，請確認後再送出。

### STEP 4　預覽與翻譯

合約建立後，下方會出現預覽，畫面和簽署人看到的一模一樣。

- 點 **繁體／簡體／English** 可以切換語言，系統會自動翻譯合約名稱、摘要和條款。
- 簽署人在簽署頁也能自己切換三種語言。
- 確認無誤後，按 **發送簽署邀請**。

> 注意：按下「發送簽署邀請」後，合約內容和簽署方資料就**鎖定，不能再修改**，請在這一步之前確認清楚。

### STEP 5　簽署進度

發出邀請後，畫面會顯示每一方的狀態卡片：

- **狀態**：待簽署、已簽署、退回修改、已拒絕、已逾期。
- **公司資料與 Email**。
- **Email 寄送結果**：已寄出、寄送失敗，或「未寄信（手動轉交）」。
- **簽署連結和「複製連結」按鈕**：如果信沒寄出，可以用 LINE、Teams 或 Email 自己轉給對方。

頁面會自動更新進度。全部簽署完成後，會出現 **下載已簽署 PDF**、**重寄完成通知** 兩個按鈕，以及完成通知的寄送結果。

## 4. 簽署人：如何簽署合約

### 4.1 打開專屬連結

簽署人會在 Email 收到主旨為「**簽署邀請／Signing invitation：合約名稱**」的信，或由起約方直接轉傳連結。點開後就是簽署頁，不需要註冊或登入。

> 這是**你個人專用**的連結，請勿轉給別人。連結**只能使用一次**，完成簽署、退回或拒絕後就會失效。

### 4.2 閱讀合約

簽署頁會依序顯示合約封面（合約編號、名稱、摘要、各方公司資料）、合約條款、附件文件，以及簽署期限。附件可以點 **開啟文件** 查看原檔，畫面上也會顯示擷取出的文字。標題列旁的語言按鈕可以切換繁體、簡體或 English。

### 4.3 三種處理方式

| 動作 | 需要填寫 | 結果 |
|---|---|---|
| **確認簽署** | 簽署人姓名＋手寫簽名＋勾選「我已閱讀合約內容，並同意以電子方式處理本次簽署」 | 你的簽署完成；全部簽署方都簽完後，合約變成「已全數簽署」 |
| **退回修改** | 在「備註／原因」寫明要修改的地方 | 合約變成「待修改」，起約方會看到你的原因 |
| **拒絕簽署** | 在「備註／原因」寫明拒絕原因 | 合約變成「已被拒絕」，其他人也不能再簽 |

**手寫簽名**：在簽名框內用滑鼠或手指簽名，簽錯了按 **清除簽名** 重簽即可。

### 4.4 簽完之後

- 畫面會顯示「已完成電子簽署」，以及目前的合約狀態。
- 全部簽署方都完成後，你會收到「**【已完成簽署】合約編號 名稱**」的 Email，信裡附上已簽署 PDF。
- 之後隨時用原本的連結再打開，就能 **下載已簽署 PDF**。連結不能再拿來簽署，但可以用來下載。

## 5. 合約管理：清單、內容頁與 PDF

### 5.1 瀏覽所有合約（`/contracts`）

點頁面上方導覽列的 **瀏覽所有合約**，或直接打開 <https://mycontractapp-911.web.app/contracts>。

- **查詢**：可以輸入合約編號、名稱、摘要、公司名稱、統一編號、代表人或 Email。
- **依狀態篩選**：草稿、已發出邀請、部分簽署、已全數簽署、已被拒絕、待修改。
- 查詢條件會保留在網址上，可以存成書籤，例如「所有部分簽署的合約」。
- 點任一筆合約，就會進入它的合約內容頁。

### 5.2 合約內容頁（`/contracts/<合約編號>`）

| 功能 | 說明 |
|---|---|
| 封面與條款 | 完整顯示合約內容，可以切換三種語言 |
| 附件 | 開啟或下載原始文件 |
| 簽署方與進度 | 每一方的公司資料、狀態、簽署時間，以及退回或拒絕的原因 |
| **找回待簽連結** | 尚未簽署的人，連結會顯示在這裡，可以隨時複製再轉傳 |
| 修改合約編號 | 輸入新編號後按 **儲存編號**，網址會跟著改 |
| 下載已簽署 PDF | 全部簽署完成後才會出現 |
| 重寄完成通知 | 全部簽署完成後才會出現 |

### 5.3 已簽署 PDF 的內容

| 頁面 | 內容 |
|---|---|
| 封面 | 你選的封面、合約名稱、摘要、各方公司與統編、合約編號、建立時間 |
| 立約當事人 | 每一方的公司名稱、統一編號、地址、代表人、Email |
| 合約條款 | 條款全文、附件名稱與 SHA-256、附件文字 |
| 簽署頁 | 每一方的角色、姓名、公司、統編、代表人、Email、簽署時間、手寫簽名 |
| 稽核紀錄 | 合約編號、簽署方數、簽署方式、PDF 產生時間、附件 SHA-256 |
| 附錄 | 如果上傳的是 PDF，原始 PDF 的每一頁 |

中文、英文字型都已內嵌在 PDF 裡，任何裝置打開都不會亂碼。

## 6. 合約與簽署狀態一覽

**合約狀態**

| 狀態 | 意思 | 下一步 |
|---|---|---|
| 草稿 | 已建立，還沒發出邀請 | 檢查內容後按「發送簽署邀請」 |
| 已發出邀請 | 邀請已發出，還沒有人簽 | 等待簽署，必要時轉傳連結 |
| 部分簽署 | 有人簽了，還有人沒簽 | 到內容頁找回待簽連結，提醒對方 |
| 已全數簽署 | 所有人都簽完了 | 下載已簽署 PDF；完成通知已自動寄出 |
| 待修改 | 有人按了「退回修改」 | 依對方原因修改後，**建立新合約**重新發送 |
| 已被拒絕 | 有人按了「拒絕簽署」 | 與對方溝通；需要的話建立新合約 |

**每一方的簽署狀態**

| 狀態 | 意思 |
|---|---|
| 待簽署 | 連結有效，等待對方處理 |
| 已簽署 | 已完成簽名 |
| 退回修改 | 對方要求修改，並留下原因 |
| 已拒絕 | 對方拒絕簽署，並留下原因 |
| 已逾期 | 超過簽署期限，連結失效 |

> 合約一旦被「退回修改」或「拒絕」，就會關閉，其他人也無法再簽。這是為了避免有人簽到舊版內容。

## 7. Email 通知

| 時機 | 收件人 | 主旨 | 內容 |
|---|---|---|---|
| 按下「發送簽署邀請」 | 每一方 | 簽署邀請／Signing invitation：合約名稱 | 各自的專屬簽署連結＋期限 |
| 最後一方簽完 | 每一方＋副本名單 | 【已完成簽署】合約編號 名稱 | 各方公司資料、完成時間、PDF 的 SHA-256；**附上已簽署 PDF**，另附收件人自己的下載連結 |

**完成通知的規則**

- 同一份合約只會**自動寄一次**。
- PDF 超過 10 MB 時，改為只附下載連結。
- 寄信失敗不會影響簽署結果。管理台會顯示「完成通知：成功 x／失敗 y」，可以按 **重寄完成通知** 再寄一次。
- 想讓自己或法務也收到副本，請維護者設定 `COMPLETION_CC`，見[第 8 章](#8-系統維護者部署與設定)。

**沒收到信？**

1. 先請對方看看垃圾郵件匣。
2. 再看管理台的寄送狀態：「未寄信」表示 SMTP 還沒設定，「寄送失敗」請檢查 SMTP 帳號密碼。
3. 不管是哪一種情況，都可以先從合約內容頁複製連結，直接轉給對方。

## 8. 系統維護者：部署與設定

### 8.1 專案位置

| 位置 | 內容 |
|---|---|
| GitHub：[MyContractApp-eSign](https://github.com/SamWang61/MyContractApp-eSign)、[E-ContractApp](https://github.com/SamWang61/E-ContractApp) | 兩個 repo 的 `firebase/` 資料夾內容相同，都是正式版 |
| 本機：`C:\Users\USER\iCloudDrive\MyContractApp-eSign-main\firebase` | 部署用的資料夾，內含你的 `functions\.env`（簽署金鑰與 SMTP 設定，不會上傳到 GitHub） |

### 8.2 更新與部署（Windows）

1. 從 GitHub 下載 ZIP，解壓後**覆蓋**到 `C:\Users\USER\iCloudDrive\MyContractApp-eSign-main`。ZIP 裡沒有 `.env`，你的金鑰會保留。
2. 雙擊 `firebase\deploy.cmd`，腳本會依序完成 7 個步驟：
   - 檢查 Node.js 和 Firebase CLI
   - 找到 Python 3.12
   - 安裝後端套件
   - 準備 `.env`（保留原本的簽署金鑰）
   - 確認 Firebase 登入
   - 部署網站、後端、Storage 規則和 Firestore 安全規則
   - 健康檢查
3. 若詢問是否刪除其他 functions，請回答 **N**。
4. 看到 `API is live ... 2026-10-16d` 就是成功。網頁沒更新的話，按 **Ctrl + F5** 強制重新整理。

只改了網頁（例如頁尾文字）時，可以在 `firebase` 資料夾執行下面這行，大約 30 秒完成：

```
firebase deploy --only hosting --project mycontractapp-911
```

### 8.3 `functions\.env` 設定

```env
# 必要：簽署連結加密金鑰（部署腳本會自動保留，請勿修改或外流）
SIGNING_TOKEN_ENCRYPTION_KEY=……

# 寄信（以 Gmail 為例；密碼請用 Google「應用程式密碼」，不是登入密碼）
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=你的帳號@gmail.com
SMTP_PASSWORD=16 碼應用程式密碼
SMTP_FROM=你的帳號@gmail.com

# 選填：合約完成時的副本收件人，多個用逗號分隔
COMPLETION_CC=sam@example.com,legal@example.com

# 選填：公司內部不加密的轉信伺服器才需要設定
# SMTP_SECURE=none
```

詳細步驟見 `firebase/docs/EMAIL_SETUP.md`。改完 `.env` 後要重新部署才會生效。

### 8.4 安全規則

網頁前端**不能直接讀寫資料庫**，所有存取都經過後端 API 驗證：

- 只有合約的建立者能查看和管理自己的合約。
- 簽署人只能透過自己的一次性連結，處理自己那一份簽署。
- 簽署連結以 SHA-256 雜湊保存並加密，資料庫裡看不到原始連結。

完整說明見 `firebase/docs/SECURITY_RULES.md`。

## 9. 常見問題與錯誤訊息

| 畫面訊息或狀況 | 原因 | 解決方式 |
|---|---|---|
| 找不到這份合約 | 合約編號打錯，或不是用建立合約的那個瀏覽器打開 | 確認編號；改用原本的瀏覽器 |
| 這個合約編號已被使用 | 同一帳號裡已經有這個編號 | 換一個編號，或沿用系統預設編號 |
| 合約編號格式不正確 | 編號需為 2–40 個字元，只能用英數字、`-`、`_`、`.`，並以英數字開頭 | 依規則修改 |
| 統一編號不正確 | 8 位數字的檢查碼不符，或含有非法字元 | 確認統編；外國公司請用英數字 |
| 每一方的 Email 不能重複 | 兩方填了同一個 Email | 每一方改用不同的 Email |
| 此連結已逾期 | 超過簽署期限 | 起約方建立新合約，重新發送 |
| 此合約已被拒絕、退回或已完成，無法再簽署 | 有人退回或拒絕，或合約已經全部簽完 | 向起約方確認最新版本 |
| 退回或拒絕時請填寫原因 | 「備註／原因」沒有填 | 寫明原因再送出 |
| 所有簽署方完成後才能下載已簽署 PDF | 還有人沒簽 | 等全部簽完；到內容頁查看是誰還沒簽 |
| 尚未登入／登入已失效 | 頁面開太久，登入已過期 | 重新整理頁面 |
| 簽署人沒收到邀請信 | SMTP 沒設定、寄送失敗，或信被歸到垃圾郵件 | 見[第 7 章](#7-email-通知)，先手動轉傳連結 |
| 換了電腦就看不到合約 | 合約綁在原本的瀏覽器 | 回到原本的電腦和瀏覽器操作 |

## 11. 附錄：編號與統編規則

**合約編號**

| 規則 | 說明 |
|---|---|
| 預設格式 | `C-YYMM001`，例如 2026 年 10 月第 1 份為 `C-2610001` |
| 流水號 | 每月從 001 重新開始；你手動用了 `005`，下一個預設就會跳到 `006` |
| 自訂 | 2–40 個字元，可用英數字、`-`、`_`、`.`，以英數字開頭 |
| 唯一性 | 同一帳號內不可重複，不分大小寫 |
| 修改 | 建立時、建立後都能改；舊編號會釋出，可以再使用 |

**統一編號**

| 情況 | 規則 |
|---|---|
| 台灣公司 | 8 位數字，依財政部 2023 年新制驗證檢查碼：各位數乘上權數 1-2-1-2-1-2-4-1，把每個乘積的十位數和個位數相加後加總，總和能被 5 整除即正確；第 7 碼為 7 時，總和加 1 能被 5 整除也算正確 |
| 外國公司 | 1–20 碼英文、數字或 `-`，例如 `US-12-3456789` |
| 個人 | 留白即可 |
